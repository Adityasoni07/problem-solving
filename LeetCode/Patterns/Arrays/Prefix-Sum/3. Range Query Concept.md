# Range Query Concept

## Idea

A **Range Query** asks for information about a **continuous subarray**.

Instead of asking about one element,

we ask about a range:

L ... R

---

## Common Range Queries

- Range Sum
- Range XOR
- Range Maximum
- Range Minimum
- Range GCD
- Range Frequency

---

## Why Range Queries Matter

A single query can be solved by looping through the range.

However, when there are **many queries** on the same array, repeatedly scanning the range becomes inefficient.

Instead, preprocess the array once and reuse the computed information.

This is the motivation behind **Prefix Sum**.

---

## Mental Model

Don't ask:

> **How do I compute this range?**

Ask:

> **Can I preprocess once and answer every range quickly?**

---

## Recognition

Think **Range Query** when you see:

- Many Queries
- Continuous Subarray
- `L ... R`
- Static Array
- Repeated Computation

---

## Key Observation

Many range queries share overlapping work.

Instead of recomputing every range,

store cumulative information once and reuse it.

Whole Prefix - Unwanted Prefix = Desired Range

---

## Important Terms

| Term        | Meaning                     |
| ----------- | --------------------------- |
| Array       | Entire sequence             |
| Subarray    | Continuous part of an array |
| Range       | Indices `[L...R]`           |
| Range Query | A question about that range |

---

## Recognition Checklist

Ask yourself:

- Is the query about a continuous range?
- Are there many such queries?
- Is the array mostly static?
- Am I repeating the same computation?

If the answer is **Yes**, a preprocessing technique such as **Prefix Sum** is often the right direction.

---

## One-Line Definition

A **Range Query** asks for information about a continuous portion of an array. Efficient solutions usually preprocess cumulative information once and reuse it to answer many queries quickly.
