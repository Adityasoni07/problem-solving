# 1. Recursion Fundamentals

> **Goal:** Understand exactly how recursion works before solving recursion problems.

---

## 1. What is Recursion?

**Recursion = a function calling itself to solve a smaller version of the same problem.**

```java
void f(int n) {
    if (n == 0) {
        return;
    }

    System.out.println(n);
    f(n - 1);
}
```

The function keeps calling itself:

```text
f(3)
 ↓
f(2)
 ↓
f(1)
 ↓
f(0)
```

The important idea is:

> **A recursive function must eventually reach a situation where it stops calling itself.**

---

# 2. The Two Essential Parts

Every basic recursive function has two important components:

```text
        Recursive Function
               |
       ┌───────┴────────┐
       ↓                ↓
   Base Case       Recursive Case
```

## 2.1 Base Case

The **base case** tells recursion when to stop.

```java
if (n == 0) {
    return;
}
```

Without a base case:

```java
void f(int n) {
    System.out.println(n);
    f(n - 1);
}
```

The function keeps calling itself until the program runs out of stack memory.

### Rule

> **Every recursion must have a clear stopping condition.**

---

## 2.2 Recursive Case

The recursive case is where the function calls itself.

```java
f(n - 1);
```

The problem should generally become **smaller or closer to the base case**.

Example:

```java
f(n - 1);  // n → n-1 → n-2 → ...
```

Bad recursion:

```java
f(n + 1);
```

if the base case is:

```java
if (n == 0)
```

Because `n` is moving away from `0`.

---

# 3. The Basic Recursion Template

A useful template:

```java
returnType function(parameters) {

    // 1. Base case
    if (baseCondition) {
        return baseValue;
    }

    // 2. Recursive call
    return function(smallerProblem);
}
```

For a `void` function:

```java
void function(parameters) {

    if (baseCondition) {
        return;
    }

    function(smallerProblem);
}
```

Think:

```text
1. Can I stop?
       ↓
2. Do a small amount of work
       ↓
3. Solve the smaller problem
```

---

# 4. First Example — Print N to 1

```java
void f(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);

    f(n - 1);
}
```

Call:

```java
f(3);
```

## Flow

```text
f(3)
 ├── print 3
 └── f(2)
      ├── print 2
      └── f(1)
           ├── print 1
           └── f(0)
                └── return
```

Output:

```text
3
2
1
```

---

# 5. What Actually Happens?

This is where recursion becomes important.

When we call:

```java
f(3);
```

Java does **not** execute everything at once.

It creates a stack of function calls.

```text
f(3)
```

calls:

```text
f(2)
```

which calls:

```text
f(1)
```

which calls:

```text
f(0)
```

At this point:

```java
if (n == 0) {
    return;
}
```

So `f(0)` finishes.

Then control returns to `f(1)`.

Then `f(1)` finishes.

Then control returns to `f(2)`.

Then `f(2)` finishes.

Then control returns to `f(3)`.

---

# 6. Call Stack

Think of recursion as a **stack of unfinished work**.

For:

```java
f(3);
```

before reaching the base case:

```text
┌─────────┐
│  f(0)   │ ← currently executing
├─────────┤
│  f(1)   │
├─────────┤
│  f(2)   │
├─────────┤
│  f(3)   │
└─────────┘
```

The last function called is the first one to finish.

This is **LIFO**:

> **Last In → First Out**

---

# 7. The Most Important Question

When learning recursion, don't ask:

> "How does the entire recursion work at once?"

Instead ask:

> **"What does this function do for ONE input?"**

For example:

```java
void f(int n) {
    if (n == 0) return;

    System.out.println(n);
    f(n - 1);
}
```

Understand:

```text
f(n):
    print n
    then ask f(n-1) to do the same thing
```

That's enough.

You don't need to mentally execute every recursive call simultaneously.

---

# 8. Work Before Recursive Call

Consider:

```java
void f(int n) {

    if (n == 0) return;

    System.out.println(n);

    f(n - 1);
}
```

The `println` happens **before** the recursive call.

Therefore:

```text
f(3)
 → print 3
 → f(2)
    → print 2
    → f(1)
       → print 1
       → f(0)
```

Output:

```text
3 2 1
```

---

# 9. Work After Recursive Call

Now change the order:

```java
void f(int n) {

    if (n == 0) return;

    f(n - 1);

    System.out.println(n);
}
```

Call:

```java
f(3);
```

Now recursion goes down first:

```text
f(3)
 ↓
f(2)
 ↓
f(1)
 ↓
f(0)
```

Then it starts returning.

```text
f(0) → return
f(1) → print 1
f(2) → print 2
f(3) → print 3
```

Output:

```text
1 2 3
```

### Key Rule

```text
Before recursive call
        ↓
Work happens while going DOWN

After recursive call
        ↓
Work happens while coming BACK UP
```

This concept is extremely important for recursion problems.

---

# 10. Example: Before + After

```java
void f(int n) {

    if (n == 0) return;

    System.out.println("Before " + n);

    f(n - 1);

    System.out.println("After " + n);
}
```

Call:

```java
f(3);
```

Execution:

```text
Before 3
Before 2
Before 1

After 1
After 2
After 3
```

Think of it as:

```text
              f(3)
          /           \
     Before 3       After 3
          |
         f(2)
      /       \
 Before 2    After 2
      |
     f(1)
   /     \
Before 1  After 1
   |
  f(0)
```

---

# 11. Recursion Has Two Phases

A very useful mental model:

```text
             RECURSION
                 |
        ┌────────┴────────┐
        ↓                 ↓
      Going Down       Coming Back
        ↓                 ↓
   Recursive calls    Return phase
```

Example:

```java
void f(int n) {

    if (n == 0) return;

    System.out.println("DOWN " + n);

    f(n - 1);

    System.out.println("UP " + n);
}
```

For `f(3)`:

```text
DOWN 3
DOWN 2
DOWN 1

UP 1
UP 2
UP 3
```

---

# 12. Return Values in Recursion

Recursion isn't only about printing.

A recursive function can **return a value**.

Example: factorial.

```java
int factorial(int n) {

    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

Mathematically:

```text
5! = 5 × 4 × 3 × 2 × 1
```

Recursive definition:

```text
factorial(5)
= 5 × factorial(4)

factorial(4)
= 4 × factorial(3)

factorial(3)
= 3 × factorial(2)

factorial(2)
= 2 × factorial(1)

factorial(1)
= 1 × factorial(0)

factorial(0)
= 1
```

Now the return phase:

```text
factorial(0) = 1

factorial(1) = 1 × 1 = 1

factorial(2) = 2 × 1 = 2

factorial(3) = 3 × 2 = 6

factorial(4) = 4 × 6 = 24

factorial(5) = 5 × 24 = 120
```

So:

```java
factorial(5)
```

returns:

```text
120
```

---

# 13. The Most Important Return Concept

Look at:

```java
return n * factorial(n - 1);
```

Don't think:

```text
return n * ???
```

and get confused.

Think:

> **"I trust \*\***`factorial(n - 1)`\***\* to solve the smaller problem and give me its answer."**

For example:

```text
factorial(5)
```

trusts:

```text
factorial(4)
```

to return `24`.

Then:

```text
5 × 24 = 120
```

This is called the **recursive trust** idea.

---

# 14. Recursive Trust

When solving recursion, use this mindset:

```text
I don't need to solve the smaller problem myself.

I trust recursion to solve it.

I only need to figure out:

"What should I do with the answer?"
```

Example:

```java
int sum(int n) {

    if (n == 0) return 0;

    return n + sum(n - 1);
}
```

For `sum(5)`:

```text
sum(5)
= 5 + sum(4)
```

Trust:

```text
sum(4) = 10
```

Therefore:

```text
5 + 10 = 15
```

---

# 15. Parameter Changes

A recursive function usually changes its parameters so that it eventually reaches the base case.

Common patterns:

```java
n - 1
n + 1
index + 1
index - 1
left + 1
right - 1
```

Example:

```java
void f(int i, int n) {

    if (i > n) return;

    System.out.println(i);

    f(i + 1, n);
}
```

Here:

```text
i = 1
i = 2
i = 3
...
i = n
```

The parameter `i` represents **where we currently are**.

---

# 16. Base Case + Progress

A recursion is usually correct when you can answer both:

### Question 1

**When does it stop?**

```java
if (i > n) return;
```

### Question 2

**Why will it eventually stop?**

```java
i + 1
```

moves `i` toward the stopping condition.

So always check:

```text
BASE CASE
   +
PROGRESS TOWARD BASE CASE
```

---

# 17. Common Recursion Mistakes

## Mistake 1 — No Base Case

```java
void f(int n) {
    f(n - 1);
}
```

❌ Never stops.

---

## Mistake 2 — Wrong Direction

```java
void f(int n) {

    if (n == 0) return;

    f(n + 1);
}
```

❌ Moving away from `0`.

---

## Mistake 3 — Forgetting Return

Wrong:

```java
int sum(int n) {

    if (n == 0) return 0;

    sum(n - 1);
}
```

The recursive result is ignored.

Correct:

```java
return n + sum(n - 1);
```

---

## Mistake 4 — Trying to Understand Everything at Once

Don't manually expand:

```text
f(100)
f(99)
f(98)
...
```

Instead understand the relationship:

```text
f(n) → f(n-1)
```

Then use a small dry run such as:

```text
n = 3
```

---

# 18. How to Dry Run Recursion

Use this process.

### Step 1 — Write the function

```java
void f(int n) {

    if (n == 0) return;

    System.out.println(n);

    f(n - 1);
}
```

### Step 2 — Start with a small value

```java
f(3);
```

### Step 3 — Follow calls downward

```text
f(3)
 ↓
f(2)
 ↓
f(1)
 ↓
f(0)
```

### Step 4 — Stop at base case

```text
f(0) → return
```

### Step 5 — Follow returns upward

If there is work after the recursive call, execute it while returning.

---

# 19. Recursion Checklist

Whenever you see a recursion problem, ask:

```text
1. What is the base case?

2. What is the smaller problem?

3. How does the parameter change?

4. Does the parameter move toward the base case?

5. What happens BEFORE the recursive call?

6. What happens AFTER the recursive call?

7. Is the function returning a value?

8. If it returns a value, what do I do with the
   smaller problem's answer?

9. What happens during the DOWN phase?

10. What happens during the UP/RETURN phase?
```

# 20. Mental Model

The most useful mental model for basic recursion:

```text
                 f(n)
                  |
          ┌───────┴────────┐
          ↓                ↓
      Base case?          No
          ↓                ↓
        STOP        Do current work
                           |
                           ↓
                       f(smaller)
                           |
                           ↓
                    Wait for answer
                           |
                           ↓
                    Continue / return
```

Or simply:

```text
          GO DOWN
             ↓
      solve smaller
             ↓
          BASE CASE
             ↓
          COME UP
```

# 21. Recursion vs Loop

Many simple recursive problems can also be solved using loops.

### Loop

```java
for (int i = 3; i >= 1; i--) {
    System.out.println(i);
}
```

### Recursion

```java
void f(int n) {

    if (n == 0) return;

    System.out.println(n);

    f(n - 1);
}
```

Both produce:

```text
3
2
1
```

But recursion becomes especially useful when the problem naturally branches:

```text
                 problem
                /       \
           choice 1    choice 2
             /             \
          ...               ...
```

This leads to topics such as:

- Tree recursion
- Backtracking
- Subsets
- Subsequences
- Permutations
- Divide and conquer
- Dynamic programming


---

# 24. Golden Rules

> **Rule 1:** Always identify the base case first.

> **Rule 2:** Every recursive call should move toward the base case.

> **Rule 3:** Trust the recursive call to solve the smaller problem.

> **Rule 4:** Code before recursion executes while going DOWN.

> **Rule 5:** Code after recursion executes while coming BACK UP.

> **Rule 6:** For return-value recursion, ask:
> **"What will the smaller call return to me?"**

> **Rule 7:** Start dry runs with small inputs like `2`, `3`, or `4`.

> **Rule 8:** Don't try to mentally execute the entire recursion. Understand the relationship between `f(n)` and `f(smaller)`.

# 25. One-Line Summary

```text
Recursion = Solve the current problem by trusting
a recursive call to solve a smaller version of it,
until the base case stops the process.
```

### Core Pattern

```text
                f(n)
                 |
          ┌──────┴──────┐
          ↓             ↓
       BASE CASE       WORK
          |             |
        STOP            ↓
                    f(smaller)
                         |
                    get answer
                         |
                         ↓
                  finish current
```
