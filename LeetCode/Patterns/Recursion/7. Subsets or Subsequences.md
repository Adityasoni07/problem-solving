# 7. Subsets / Subsequences

> **Goal:** Master the most important **decision-based recursion pattern**: for every element, decide whether to **take it or skip it**.

This pattern is the foundation for:

- Subsets
- Subsequences
- Include/Exclude recursion
- Many backtracking problems
- Combination problems
- Dynamic programming on choices

---

# 1. The Core Idea

Suppose:

```text
arr = [1, 2, 3]
```

For every element, we have two choices:

```text
TAKE it
OR
SKIP it
```

For `1`:

```text
              1
             / \
          TAKE  SKIP
```

Then for `2`:

```text
                  []
                /    \
              TAKE   SKIP
               1       1
              / \     / \
           TAKE SKIP TAKE SKIP
             2     2    2    2
```

And then for `3`.

This creates a **binary decision tree**.

---

# 2. What Is a Subsequence?

A **subsequence** is formed by deleting zero or more elements while **preserving the original order**.

Example:

```text
arr = [1, 2, 3]
```

Valid subsequences:

```text
[]
[1]
[2]
[3]
[1,2]
[1,3]
[2,3]
[1,2,3]
```

Notice:

```text
[1,3]
```

is valid because `1` comes before `3`.

But:

```text
[3,1]
```

is NOT a subsequence because the original order was:

```text
1 → 2 → 3
```

---

# 3. What Is a Subset?

A **subset** is a collection of elements chosen from a set.

For:

```text
{1, 2, 3}
```

subsets are:

```text
{}
{1}
{2}
{3}
{1,2}
{1,3}
{2,3}
{1,2,3}
```

For a simple array with distinct elements, the generated subsets have the same collection of results as the subsequences.

The important difference is the **concept**:

```text
Subset
→ focuses on selection / membership

Subsequence
→ focuses on selection while preserving order
```

---

# 4. The Most Important Difference

Consider:

```text
[1, 2, 3]
```

### Subsequence

You cannot reorder.

```text
[1,3]  ✓
[3,1]  ✗
```

### Subset

Order generally does not matter.

```text
{1,3}
```

represents the same set as:

```text
{3,1}
```

In coding problems, however, the output format may still require a particular ordering.

---

# 5. The Key Recursive Question

At every element ask:

> **"Should I include this element or exclude it?"**

For:

```text
[1,2,3]
```

At index `0`:

```text
element = 1
```

Choices:

```text
take 1
skip 1
```

Then move to:

```text
index = 1
```

and make the same decision for `2`.

Then:

```text
index = 2
```

and make the decision for `3`.

Finally:

```text
index == n
```

means:

> We have made a decision for every element.

That becomes the base case.

---

# 6. The Fundamental Template

This is the pattern you should memorize **conceptually**, not mechanically:

```java
void solve(int index) {

    if (index == arr.length) {
        // process current answer
        return;
    }

    // TAKE
    current.add(arr[index]);
    solve(index + 1);

    // UNDO
    current.remove(current.size() - 1);

    // SKIP
    solve(index + 1);
}
```

The structure is:

```text
              solve(index)
                 /     \
              TAKE     SKIP
               /         \
        solve(index+1) solve(index+1)
```

---

# 7. Why Do We Need `Undo`?

Suppose:

```text
arr = [1,2]
```

Start:

```text
current = []
```

Take `1`:

```text
current = [1]
```

Then take `2`:

```text
current = [1,2]
```

We finish that branch.

Now we need to explore:

```text
[1]
```

instead of:

```text
[1,2]
```

So we remove `2`.

```text
current = [1]
```

Then eventually remove `1`:

```text
current = []
```

This is **backtracking**.

---

# 8. The Decision Tree for `[1,2]`

```text
                         []
                       /    \
                    TAKE    SKIP
                     1        -
                    / \      / \
                 TAKE SKIP TAKE SKIP
                   2     -    2     -
```

Results:

```text
[1,2]
[1]
[2]
[]
```

Depending on the traversal order, the output may be:

```text
[1,2]
[1]
[2]
[]
```

or another valid ordering.

---

# 9. Complete Tree for `[1,2,3]`

The important structure is:

```text
                           []
                       /        \
                     1           -
                   /   \       /   \
                1,2     1      2     -
               /  \    / \    / \   / \
            1,2,3 1,2 1,3 1  2,3 2  3  []
```

Every level makes one decision:

```text
Level 0 → decide about 1
Level 1 → decide about 2
Level 2 → decide about 3
Level 3 → all decisions complete
```

---

# 10. Why Are There `2^N` Subsets?

Every element has exactly two choices:

```text
TAKE
SKIP
```

For `N` elements:

```text
2 × 2 × 2 × ... × 2
```

`N` times.

Therefore:

```text
2^N
```

subsets/subsequences.

Examples:

```text
N = 1 → 2
N = 2 → 4
N = 3 → 8
N = 4 → 16
N = 5 → 32
```

General formula:

```text
Number of subsets = 2^N
```

---

# 11. Why Does the Tree Have `2^N` Leaves?

At every level:

```text
             node
            /    \
         TAKE    SKIP
```

Each element doubles the number of possibilities.

```text
Level 0 → 1
Level 1 → 2
Level 2 → 4
Level 3 → 8
...
Level N → 2^N
```

The leaves represent complete decisions.

Therefore:

```text
Leaves = 2^N
```

---

# 12. Important Complexity Insight

If you need to **generate all subsets**, you cannot do better than roughly:

```text
O(2^N)
```

because there are already:

```text
2^N
```

answers.

If you also copy/store each subset, the total output cost can be larger depending on the total size of all generated subsets.

For basic recursion analysis, remember:

```text
Number of answers → 2^N
```

# 13. Subset Code — LeetCode 78

LeetCode **78 — Subsets** is the most important problem for this pattern.

```java
class Solution {

    public List<List<Integer>> subsets(int[] nums) {

        List<List<Integer>> ans = new ArrayList<>();

        solve(0, nums, new ArrayList<>(), ans);

        return ans;
    }

    private void solve(
        int index,
        int[] nums,
        List<Integer> current,
        List<List<Integer>> ans
    ) {

        if (index == nums.length) {
            ans.add(new ArrayList<>(current));
            return;
        }

        // TAKE
        current.add(nums[index]);

        solve(index + 1, nums, current, ans);

        // UNDO
        current.remove(current.size() - 1);

        // SKIP
        solve(index + 1, nums, current, ans);
    }
}
```

---

# 14. Understand the Function Meaning

This function:

```java
solve(index, nums, current, ans)
```

means:

> **"I have already made decisions for elements before `index`. Now I need to decide what to do with elements from `index` onward."**

This sentence is extremely important.

For:

```text
nums = [1,2,3]
```

At:

```text
index = 0
```

we haven't decided anything.

At:

```text
index = 1
```

we have already decided what to do with `1`.

At:

```text
index = 2
```

we have already decided what to do with `1` and `2`.

At:

```text
index = 3
```

all decisions are complete.

Therefore:

```java
if (index == nums.length)
```

is the base case.

---

# 15. The Most Important State

For subset generation, we usually maintain:

```text
index
current path
```

### `index`

Tells us:

> Which element are we deciding about now?

### `current`

Tells us:

> Which elements have we chosen so far?

So:

```text
solve(index, current)
```

represents:

```text
"What choices have I made so far,
and what element do I decide about next?"
```

# 17. The Most Important Backtracking Sequence

For:

```java
current.add(nums[index]);
solve(index + 1);
current.remove(current.size() - 1);
solve(index + 1);
```

memorize the **logic**:

```text
MAKE CHOICE
    ↓
RECURSE
    ↓
UNDO CHOICE
    ↓
TRY NEXT CHOICE
```

This is the foundation of backtracking.

---

# 18. Why `current.remove()` Is Between the Calls

This is a very common beginner confusion.

Wrong:

```java
current.add(nums[index]);

solve(index + 1);

solve(index + 1);

current.remove(current.size() - 1);
```

Why wrong?

Because the second branch would still contain the element.

Correct:

```java
current.add(nums[index]);

solve(index + 1);

current.remove(current.size() - 1);

solve(index + 1);
```

Because:

```text
First branch:
element is present

Second branch:
element must be absent
```

So we must restore the state between branches.

# 19. Another Way — No Explicit `current`

For some problems, you can build the subsequence using a string or return values.

Example:

```java
void solve(String s, int index, String current) {

    if (index == s.length()) {
        System.out.println(current);
        return;
    }

    // Take
    solve(s, index + 1, current + s.charAt(index));

    // Skip
    solve(s, index + 1, current);
}
```

This is easier to understand initially.

But repeatedly creating strings can be less efficient.

For learning the pattern, both approaches are useful.

# 20. Subsets vs Subsequences in Recursion

For:

```text
[1,2,3]
```

the decision tree is the same:

```text
Take
OR
Skip
```

because both are generated by selecting elements while moving from left to right.

Therefore:

```text
Subset generation
        ≈
Subsequence generation
```

for many basic recursion problems.

But remember:

```text
Subsequence:
ORDER MUST BE PRESERVED

Subset:
ORDER IS NOT THE CONCEPTUAL FOCUS
```

# 21. Example — All Subsequences of `"abc"`

At every character:

```text
a → take / skip
b → take / skip
c → take / skip
```

Results:

```text
"abc"
"ab"
"ac"
"a"
"bc"
"b"
"c"
""
```

The exact order depends on whether you process:

```text
TAKE → SKIP
```

or:

```text
SKIP → TAKE
```

# 22. Include / Exclude Pattern

You will see another name for the same pattern:

> **Include / Exclude**

For each element:

```text
              element
              /     \
          INCLUDE  EXCLUDE
```

This is the same as:

```text
TAKE
SKIP
```

So remember:

```text
Take / Skip
    =
Include / Exclude
```

# 25. Subsequence With a Condition

Suppose:

```text
arr = [1,2,3]
target = 3
```

Find whether there exists a subsequence whose sum is `3`.

At each element:

```text
Take
OR
Skip
```

If take:

```text
sum += arr[index]
```

If skip:

```text
sum stays the same
```

State:

```text
solve(index, currentSum)
```

Base case:

```text
index == n
```

Then check:

```text
currentSum == target
```

---

# 26. Count Subsequences

Instead of storing every subsequence, we can count them.

Suppose:

```text
Count subsequences whose sum = target
```

At every index:

```text
take
+
skip
```

Therefore:

```text
count(index, sum)
=
count(take)
+
count(skip)
```

This is a very important multiple-recursion pattern.

---

# 27. Return-Based Decision Recursion

Example:

```java
int count(int[] nums, int index, int target, int sum) {

    if (index == nums.length) {
        return sum == target ? 1 : 0;
    }

    int take = count(
        nums,
        index + 1,
        target,
        sum + nums[index]
    );

    int skip = count(
        nums,
        index + 1,
        target,
        sum
    );

    return take + skip;
}
```

Thinking:

```text
                   current problem
                         |
                 ┌───────┴───────┐
                 ↓               ↓
               TAKE            SKIP
                 ↓               ↓
              count           count
                 ↓               ↓
              answer          answer
                 └───────┬───────┘
                         ↓
                       ADD
```

# 28. Three Common Subset/Subsequence Patterns

## Pattern 1 — Generate

```text
Take
Skip
```

Return/store every complete answer.

Example:

```text
78 — Subsets
```

---

## Pattern 2 — Find One

```text
Take
OR
Skip
```

Stop when a valid answer is found.

Example:

```text
"Does a subsequence satisfy this condition?"
```

---

## Pattern 3 — Count

```text
Take
+
Skip
```

Return:

```text
number from take branch
+
number from skip branch
```

This pattern becomes extremely important in DP.

# 29. Generate vs Find vs Count

This distinction is extremely useful.

### Generate

```text
Need ALL answers
```

Example:

```text
78 — Subsets
```

### Find

```text
Need ANY ONE valid answer
```

Use:

```text
if (take) return true;
if (skip) return true;
return false;
```

### Count

```text
Need NUMBER of valid answers
```

Use:

```text
return take + skip;
```

### Optimize

```text
Need BEST answer
```

Often:

```text
return max(take, skip);
```

This is the bridge to Dynamic Programming.

---

# 30. The Four Return Patterns

Decision recursion often becomes one of these:

### Existence

```java
return take || skip;
```

Meaning:

> Does at least one branch work?

---

### Counting

```java
return take + skip;
```

Meaning:

> How many branches work?

---

### Maximum

```java
return Math.max(take, skip);
```

Meaning:

> Which branch gives the best answer?

---

### Minimum

```java
return Math.min(take, skip);
```

Meaning:

> Which branch gives the smallest answer?

This is a powerful pattern to recognize.

# 31. Subsets With Duplicates

Consider:

```text
[1,2,2]
```

If we blindly use:

```text
Take
Skip
```

we can generate duplicate subsets.

For example, choosing the first `2` versus the second `2` can produce the same result.

That's why:

```text
78 — Subsets
```

should come before:

```text
90 — Subsets II
```

First master the decision tree.

Then learn how to control duplicate branches.

---

# 32. Subsets II — Important Concept

For:

```text
[1,2,2]
```

we usually sort first:

```text
[1,2,2]
```

Then at the same recursion level, avoid choosing duplicate values more than once.

The key idea:

```text
Same level
+
Same value
=
skip duplicate branch
```

This is more advanced backtracking.

Don't mix this logic into your understanding of basic subsets.

# 33. Subsets vs Permutations

This distinction is extremely important.

### Subsets

At every element:

```text
Take
Skip
```

Example:

```text
[1,2,3]

[1,3]
```

---

### Permutations

At every position:

```text
Choose one of the remaining elements.
```

Example:

```text
[1,2,3]

123
132
213
231
312
321
```

The recursion state is different.

Subsets:

```text
index
```

Permutations:

```text
used elements / remaining choices
```

# 34. Subsequence vs Subarray

This is another important distinction.

### Subsequence

Can skip elements.

```text
[1, 2, 3, 4]

[1,3,4] ✓
```

Elements do not need to be contiguous.

---

### Subarray

Must be contiguous.

```text
[1,2,3,4]

[2,3] ✓
[1,3] ✗
```

because `1` and `3` are not adjacent.

So:

```text
Subsequence
→ skip allowed

Subarray
→ skip not allowed
```


# 36. The Most Important Recursion Tree

For `nums = [1,2,3]`:

```text
                              []
                           /      \
                        TAKE     SKIP
                          1         -
                       /    \     /    \
                    TAKE   SKIP TAKE  SKIP
                      2       -    2      -
                    / \     / \  / \    / \
                   3   -   3   - 3  -  3   -
```

Leaves:

```text
[1,2,3]
[1,2]
[1,3]
[1]
[2,3]
[2]
[3]
[]
```

The exact traversal order depends on whether you choose:

```text
TAKE → SKIP
```

or:

```text
SKIP → TAKE
```

# 37. The Most Important State Invariant

At every recursive call:

> **`current` contains exactly the elements chosen from the indices before `index`.**

Example:

```text
solve(2, [1])
```

means:

```text
We already decided about:
1

Current chosen elements:
[1]

Next decision:
element at index 2
```

This invariant makes the recursion much easier to understand.

---

# 38. Why We Don't Need to Store "Skip"

Notice:

```java
// TAKE
current.add(nums[index]);
solve(index + 1, ...);
current.remove(current.size() - 1);

// SKIP
solve(index + 1, ...);
```

We don't explicitly add anything for skip.

Why?

Because:

```text
current
```

already contains exactly what we have chosen.

If we don't add the current element:

```text
current remains unchanged
```

That automatically represents **skip**.

---

# 39. The Most Common Beginner Confusion

You may think:

> "If I call `solve(index + 1)` for skip, how does the program know that I skipped the element?"

It knows because the current path did not change.

Example:

```text
Before decision:
current = [1]

Current element:
2
```

### Take

```text
current.add(2)

current = [1,2]
```

### Undo

```text
current.remove(2)

current = [1]
```

### Skip

```text
solve(index + 1)
```

Current remains:

```text
[1]
```

So the recursive call naturally represents:

```text
"I skipped 2."
```

# 40. Common Mistakes

## Mistake 1 — Forgetting Undo

Wrong:

```java
current.add(nums[index]);
solve(index + 1);

solve(index + 1);
```

The second branch still sees the element.

Correct:

```java
current.add(nums[index]);
solve(index + 1);

current.remove(current.size() - 1);

solve(index + 1);
```

---

## Mistake 2 — Adding to Result Directly

Wrong:

```java
ans.add(current);
```

because `current` is mutable.

Correct:

```java
ans.add(new ArrayList<>(current));
```

You need to store a **copy** of the current path.

---

## Mistake 3 — Wrong Base Case

The base case should usually mean:

```text
We have made a decision for every element.
```

So:

```java
if (index == nums.length)
```

---

## Mistake 4 — Mixing Index and Path

Remember:

```text
index
→ next decision

current
→ decisions already made
```

---

## Mistake 5 — Thinking Subsets Require Reordering

They don't.

The basic recursive generation moves:

```text
index → index + 1
```

so the original order is naturally preserved.

# 48. Golden Rules

> **Rule 1:** At every element, think **Take OR Skip**.

> **Rule 2:** `index` represents the next element whose decision hasn't been made.

> **Rule 3:** `current/path` represents the elements chosen so far.

> **Rule 4:** After taking an element, recurse, then **undo** the choice.

> **Rule 5:** Skip means simply recurse without adding the current element.

> **Rule 6:** At `index == n`, every decision is complete.

> **Rule 7:** There are `2^N` possible subsets because every element has two choices.

> **Rule 8:** Subsequence order must be preserved.

> **Rule 9:** When generating answers, store a copy of the current path.

> **Rule 10:** `Take + Skip` is the foundation of many backtracking and DP problems.

# 49. One-Line Summary

> **Subsets/Subsequences recursion = process elements from left to right, make a Take/Skip decision for each element, recursively explore both choices, and undo the Take choice when backtracking.**

### Core Pattern

```text
                         solve(index)
                              |
                    "Take or Skip?"
                       /         \
                    TAKE         SKIP
                     |             |
               add element     unchanged
                     |             |
               solve(index+1) solve(index+1)
                     |
                   UNDO
                     |
               explore next branch
```

### The Pattern to Remember

```text
             DECISION
                |
          ┌─────┴─────┐
          ↓           ↓
        TAKE         SKIP
          ↓           ↓
       RECURSE      RECURSE
          ↓           ↓
        UNDO           |
          └─────┬─────┘
                ↓
          NEXT DECISION
```

**Most important problem:** `78 — Subsets`

If you can completely understand the recursion tree, `current`, `index`, `add → recurse → remove`, and why there are `2^N` leaves in **78**, you have learned the core pattern behind a huge number of recursion/backtracking problems.
