# 2. Recursive Thinking

> **Goal:** Learn how to _think_ recursively instead of trying to trace every call manually.

Recursion becomes much easier when you stop thinking:

> "How will all these recursive calls execute?"

and start thinking:

> **"How can I solve this problem using the solution to a smaller version of the same problem?"**

---

# 1. What Is Recursive Thinking?

Suppose the problem is:

> Print numbers from `1` to `N`.

For `N = 5`:

```text
1 2 3 4 5
```

Instead of thinking about all five numbers, think:

```text
Print 1 → 5
=
Print 1 → 4
+
Print 5
```

So:

```text
problem(N)
    ↓
solve problem(N - 1)
    ↓
handle N
```

This is the heart of recursive thinking.

---

# 2. The Core Question

Whenever you see a recursion problem, ask:

> **"If I already knew how to solve the smaller problem, could I solve the current problem easily?"**

This is the most important question in recursion.

For example:

### Problem

Find the sum:

```text
1 + 2 + 3 + 4 + 5
```

Think:

```text
sum(5)
=
5 + sum(4)
```

If I already know:

```text
sum(4) = 10
```

then:

```text
sum(5) = 5 + 10
        = 15
```

I don't need to calculate `sum(4)` myself.

I **trust recursion** to do it.

---

# 3. The Three-Step Thinking Process

For most basic recursive problems:

```text
        Problem(N)
             |
             ↓
     1. Base Case
             |
             ↓
     2. Smaller Problem
             |
             ↓
     3. Combine / Do Current Work
```

More practically:

```text
1. What is the smallest problem I can solve directly?

2. How can I reduce the current problem to a smaller problem?

3. Once the smaller problem is solved,
   how do I use its result to solve the current problem?
```

---

# 4. Example — Sum of 1 to N

Problem:

```text
sum(5)
```

### Step 1 — Find the smaller problem

```text
sum(5)
→ sum(4)
```

### Step 2 — Trust the smaller problem

Assume:

```text
sum(4) = 10
```

### Step 3 — Solve the current problem

```text
sum(5)
= 5 + sum(4)
= 5 + 10
= 15
```

Therefore:

```java
int sum(int n) {

    if (n == 0) {
        return 0;
    }

    return n + sum(n - 1);
}
```

The important part isn't memorizing this code.

The important part is the thought:

```text
sum(n)
=
n + sum(n - 1)
```

---

# 5. The "Trust" Method

This is one of the most powerful techniques for recursion.

Suppose you write:

```java
int sum(int n) {
    if (n == 0) return 0;

    return n + sum(n - 1);
}
```

Don't think:

```text
"But how does sum(n - 1) work?"
```

Instead think:

> **"I trust `sum(n - 1)` to correctly return the sum from `1` to `n - 1`."**

Then your job is only:

```text
current answer
=
current value + smaller answer
```

So:

```text
sum(n)
=
n + sum(n-1)
```

That's recursive thinking.

---

# 6. Don't Solve the Smaller Problem Yourself

This is where beginners often get stuck.

Suppose:

```java
int factorial(int n) {
    if (n == 0) return 1;

    return n * factorial(n - 1);
}
```

For:

```text
factorial(5)
```

Don't manually think:

```text
5 × 4 × 3 × 2 × 1
```

Instead:

```text
factorial(5)
=
5 × factorial(4)
```

Trust:

```text
factorial(4) = 24
```

Then:

```text
5 × 24 = 120
```

Your responsibility:

```text
Solve CURRENT problem
```

Recursion's responsibility:

```text
Solve SMALLER problem
```

# 7. Recursive Thinking Template

For a problem that reduces by one:

```java
function(n) {

    if (baseCase) {
        return answer;
    }

    // Current work
    return currentWork + function(n - 1);
}
```

Think:

```text
                function(n)
                     |
                     ↓
             Can I solve directly?
                  /       \
                YES        NO
                 |          |
                STOP    function(n-1)
                            |
                            ↓
                     smaller answer
                            |
                            ↓
                    combine with n
```

# 8. Example — Factorial

Mathematical definition:

```text
n! = n × (n-1)!
```

Therefore:

```text
factorial(n)
=
n × factorial(n-1)
```

Base case:

```text
0! = 1
```

Code:

```java
int factorial(int n) {

    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

### Thinking

For `factorial(5)`:

```text
Current problem:
factorial(5)

Smaller problem:
factorial(4)

Current work:
5 × answer_of_factorial(4)
```

That's all you need.

---

# 9. Example — Power

Problem:

```text
2^5
```

Think mathematically:

```text
2^5
=
2 × 2^4
```

Therefore:

```text
power(x, n)
=
x × power(x, n-1)
```

Base case:

```text
x^0 = 1
```

Code:

```java
int power(int x, int n) {

    if (n == 0) {
        return 1;
    }

    return x * power(x, n - 1);
}
```

Recursive thinking:

```text
power(2, 5)
    ↓
2 × power(2, 4)
          ↓
      smaller problem
```

# 10. Example — Print 1 to N

Now consider a problem where we don't return a value.

```text
Print:
1 2 3 4 5
```

Ask:

> If I already knew how to print `1 → 4`, what remains?

Answer:

```text
Print 1 → 4
+
Print 5
```

Therefore:

```java
void print(int n) {

    if (n == 0) {
        return;
    }

    print(n - 1);

    System.out.println(n);
}
```

Notice something important:

```text
print(n - 1)
```

comes **before**:

```text
print(n)
```

Therefore the smaller values are printed first.

---

# 11. Example — Print N to 1

Now:

```text
5 4 3 2 1
```

Ask:

> If I already knew how to print `4 → 1`, what should happen with `5`?

Print `5` first:

```java
void print(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);

    print(n - 1);
}
```

Thinking:

```text
print(5)
=
print 5
+
print(4 → 1)
```

---

# 12. The Position of the Recursive Call Matters

Compare:

### Recursive call first

```java
print(n - 1);
System.out.println(n);
```

Produces:

```text
1 2 3 4 5
```

### Recursive call second

```java
System.out.println(n);
print(n - 1);
```

Produces:

```text
5 4 3 2 1
```

So ask:

> **Should the current work happen before or after the smaller problem?**

This single question solves many basic recursion problems.

# 13. Recursive Thinking With Arrays

Suppose:

```text
arr = [2, 5, 7, 1, 9]
```

Problem:

> Find the maximum element.

Instead of thinking about the entire array:

```text
[2, 5, 7, 1, 9]
```

think:

```text
Maximum of first 5 elements
=
max(
    maximum of first 4 elements,
    element at index 4
)
```

So:

```text
max(0...n-1)
=
max(
    max(0...n-2),
    arr[n-1]
)
```

Code:

```java
int max(int[] arr, int n) {

    if (n == 1) {
        return arr[0];
    }

    int smallerAnswer = max(arr, n - 1);

    return Math.max(smallerAnswer, arr[n - 1]);
}
```

The thinking is:

```text
1. Ask recursion for maximum of smaller array.

2. Compare that answer with current element.

3. Return the better one.
```

---

# 14. Recursive Thinking With Strings

Problem:

> Check whether a string is a palindrome.

Example:

```text
"madam"
```

Think:

```text
First character == Last character
AND
middle part is a palindrome
```

So:

```text
isPalindrome(left, right)
=
arr[left] == arr[right]
AND
isPalindrome(left+1, right-1)
```

Base case:

```text
left >= right
```

because there is nothing left to compare.

Code:

```java
boolean palindrome(String s, int left, int right) {

    if (left >= right) {
        return true;
    }

    if (s.charAt(left) != s.charAt(right)) {
        return false;
    }

    return palindrome(s, left + 1, right - 1);
}
```

This is recursive thinking:

```text
Current problem
     ↓
Check current pair
     ↓
Smaller problem
     ↓
Check inner part
```

# 15. Think in Terms of "State"

A recursive function's parameters usually represent the **current state** of the problem.

For example:

```java
void solve(int index, int n)
```

Here:

```text
index = where I am
n     = where I need to stop
```

For arrays:

```java
solve(int index)
```

might mean:

```text
"I am currently processing index."
```

For two pointers:

```java
solve(int left, int right)
```

might mean:

```text
"I currently need to solve the range [left, right]."
```

This is extremely important for harder recursion.

---

# 16. Ask: "What Does My Parameter Mean?"

Before writing recursion, define your function in plain English.

Bad:

```java
solve(int i)
```

without knowing what `i` means.

Good:

```text
solve(i) means:
"solve the problem starting from index i."
```

Or:

```text
solve(n) means:
"calculate the answer for numbers 1 through n."
```

Or:

```text
solve(left, right) means:
"solve the problem inside the range [left, right]."
```

This is called defining the **function's meaning**.

---

# 17. Function Contract

Before coding, write one sentence:

```text
solve(parameters) means ______________________.
```

Examples:

```text
sum(n)
→ returns the sum from 1 to n.

factorial(n)
→ returns n!.

max(arr, n)
→ returns the maximum among the first n elements.

palindrome(s, left, right)
→ returns whether s[left...right] is a palindrome.

print(n)
→ prints numbers from 1 to n.
```

Once this sentence is clear, the recursive code becomes much easier.

# 18. The "One Level" Rule

When solving recursion, focus on **one level**.

Suppose:

```java
int sum(int n) {
    if (n == 0) return 0;

    return n + sum(n - 1);
}
```

Don't mentally execute:

```text
sum(5)
sum(4)
sum(3)
sum(2)
sum(1)
sum(0)
```

Instead focus on:

```text
sum(5)
```

Ask:

```text
What does sum(5) need?

It needs:
5 + sum(4)
```

Then trust:

```text
sum(4)
```

That's enough.

---

# 19. "I Trust Recursion" Rule

This is the mindset you should develop:

```text
                    solve(n)
                       |
                       ↓
              "Can I solve n?"
                       |
                      Yes
                       ↓
                     STOP

                      No
                       ↓
             "Can I reduce n?"
                       |
                       ↓
                  solve(smaller)
                       |
                       ↓
              TRUST THE ANSWER
                       |
                       ↓
              Finish solve(n)
```

You are not responsible for understanding every recursive call individually.

You are responsible for correctly defining:

```text
CURRENT PROBLEM
       ↓
SMALLER PROBLEM
       ↓
CURRENT WORK
```

# 20. How to Convert a Loop Into Recursion

This is a very useful exercise.

Loop:

```java
for (int i = 1; i <= n; i++) {
    System.out.println(i);
}
```

Identify the changing variable:

```text
i
```

Identify the stopping condition:

```text
i > n
```

Then recursion:

```java
void print(int i, int n) {

    if (i > n) {
        return;
    }

    System.out.println(i);

    print(i + 1, n);
}
```

Mapping:

```text
Loop                    Recursion
---------------------------------------
initialization    →     parameters
condition         →     base case
body              →     current work
i++               →     recursive call
```

---

# 21. Another Loop → Recursion Example

Loop:

```java
int sum = 0;

for (int i = 1; i <= n; i++) {
    sum += i;
}
```

Recursive thinking:

```text
sum(n)
=
n + sum(n - 1)
```

Code:

```java
int sum(int n) {

    if (n == 0) {
        return 0;
    }

    return n + sum(n - 1);
}
```

The loop's repeated state:

```text
i = 1
i = 2
i = 3
...
```

becomes recursive state:

```text
sum(1)
sum(2)
sum(3)
...
```

# 22. When the Problem Doesn't Reduce by One

Not every recursion is:

```text
n → n - 1
```

Sometimes:

```text
n → n / 2
```

Example: Binary Search.

```text
Search entire array
       ↓
Check middle
       ↓
Search only left half
OR
Search only right half
```

The problem becomes:

```text
N
↓
N/2
↓
N/4
↓
N/8
...
```

This is still recursive thinking.

The key idea is:

> **Make the problem smaller.**

Not necessarily:

> **Subtract exactly 1.**

---

# 23. Recursive Thinking in Binary Search

Suppose:

```text
[1, 3, 5, 7, 9, 11, 13]
```

Search for `9`.

Think:

```text
Current range:
[1 ... 13]

Check middle:
7

9 > 7

Therefore:
Ignore the left half.

New problem:
[9, 11, 13]
```

Then recurse on the smaller range.

The function meaning might be:

```text
binarySearch(left, right)
=
"Search for target inside [left, right]."
```

# 24. Recursion Is About Problem Reduction

The size of the problem can reduce in different ways:

```text
Linear reduction:

N
↓
N-1
↓
N-2
↓
N-3
```

```text
Half reduction:

N
↓
N/2
↓
N/4
↓
N/8
```

```text
Range reduction:

[left, right]
      ↓
[left+1, right-1]
```

```text
Branching:

             problem
             /     \
          choice   choice
            /         \
         problem     problem
```

The common idea:

> **Each recursive call should represent a smaller subproblem.**

# 25. The Biggest Beginner Trap

### Wrong mindset

```text
"I need to know exactly what every recursive call will return."
```

### Better mindset

```text
"I need to know what my current function means."

"I need to reduce the problem."

"I trust recursion to solve the smaller problem."

"I only need to combine that answer with my current state."
```

# 26. A General Recipe for Recursive Problems

When you encounter a new problem:

## Step 1 — Define the function

Write:

```text
solve(...) means __________________________.
```

---

## Step 2 — Find the smallest problem

Ask:

```text
What is the simplest input I can solve directly?
```

That becomes the base case.

---

## Step 3 — Find the smaller problem

Ask:

```text
How can I reduce the current problem?
```

Examples:

```text
n → n-1

index → index+1

left,right → left+1,right-1

n → n/2
```

---

## Step 4 — Trust recursion

Say:

```text
"I assume solve(smaller) gives me the correct answer."
```

---

## Step 5 — Solve the current level

Ask:

```text
"Given the smaller answer, what should I do now?"
```

---

## Step 6 — Check progress

Make sure every call moves toward the base case.

---

# 27. Recursive Thinking Formula

A very useful formula:

```text
             CURRENT PROBLEM
                    |
                    ↓
             SMALLER PROBLEM
                    |
                    ↓
             RECURSIVE ANSWER
                    |
                    ↓
             CURRENT WORK
                    |
                    ↓
              CURRENT ANSWER
```

In code:

```java
Answer solve(State state) {

    if (baseCase(state)) {
        return baseAnswer;
    }

    Answer smaller = solve(smallerState);

    return combine(state, smaller);
}
```

Not every recursion literally follows this exact code structure, but this mental model is extremely useful.

# 29. Signs That You Are Thinking Recursively

You are improving when you can look at a problem and naturally say:

```text
"This problem can be reduced to..."
```

For example:

```text
sum(n)
→ sum(n-1)

factorial(n)
→ factorial(n-1)

palindrome(left,right)
→ palindrome(left+1,right-1)

binarySearch(left,right)
→ binarySearch(smaller half)
```

And then:

```text
"I trust the smaller call."

"Now what do I do with its answer?"
```

# 30. What You Should NOT Do

Avoid these habits:

### ❌ Memorizing recursive code

```text
return n * factorial(n-1);
```

without understanding why.

### ❌ Drawing huge recursion trees for simple linear recursion

You usually only need:

```text
f(n)
 ↓
f(n-1)
 ↓
base
```

### ❌ Solving the smaller problem manually

Don't calculate:

```text
sum(4)
```

inside your reasoning for:

```text
sum(5)
```

Trust recursion.

### ❌ Thinking recursion is magic

Every recursive call is simply another function call with its own state.

# 33. One-Line Summary

> **Recursive thinking means defining the current problem in terms of a smaller version of the same problem, trusting recursion to solve that smaller problem, and then handling the current state.**

### Core Pattern

```text
          solve(problem)
                |
                ↓
        Can I solve directly?
           /          \
         YES           NO
          |             |
        return      reduce problem
                        |
                        ↓
                 solve(smaller)
                        |
                        ↓
                 trust answer
                        |
                        ↓
                 current work
                        |
                        ↓
                     return
```
