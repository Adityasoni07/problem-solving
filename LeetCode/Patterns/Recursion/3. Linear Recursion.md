# 3. Linear Recursion

> **Goal:** Master the simplest and most important recursion pattern: **one recursive call per function call**.

---

# 1. What Is Linear Recursion?

A recursive function is called **linear recursion** when each function call makes **at most one recursive call**.

Example:

```java
void f(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);

    f(n - 1);
}
```

The call structure is:

```text
f(5)
 ↓
f(4)
 ↓
f(3)
 ↓
f(2)
 ↓
f(1)
 ↓
f(0)
```

There is only **one path**.

That's why it is called **linear recursion**.

---

# 2. The Basic Shape

The most common pattern is:

```text
f(n)
 ↓
f(n - 1)
 ↓
f(n - 2)
 ↓
...
 ↓
base case
```

In code:

```java
void f(int n) {

    if (baseCase) {
        return;
    }

    // current work

    f(smallerProblem);
}
```

or:

```java
returnType f(int n) {

    if (baseCase) {
        return baseValue;
    }

    // current work

    return f(smallerProblem);
}
```

---

# 3. Linear vs Multiple Recursion Calls

### Linear recursion

```java
f(n) {
    f(n - 1);
}
```

One recursive call.

```text
f(5)
 ↓
f(4)
 ↓
f(3)
 ↓
f(2)
```

### Multiple recursion

```java
f(n) {
    f(n - 1);
    f(n - 2);
}
```

Two recursive calls.

```text
        f(5)
       /    \
    f(4)    f(3)
    / \      / \
  f(3) f(2) f(2) f(1)
```

That is **not linear recursion**.

> **Linear recursion = at most one recursive call from each function call.**

---

# 4. The Main Mental Model

For linear recursion, think:

```text
CURRENT
   ↓
SMALLER
   ↓
SMALLER
   ↓
SMALLER
   ↓
BASE CASE
```

Then:

```text
CURRENT
   ↑
SMALLER
   ↑
SMALLER
   ↑
SMALLER
```

So there are still two phases:

```text
Going Down
    ↓
Base Case
    ↓
Coming Back Up
```

# 8. Linear Recursion With Return Values

Linear recursion becomes especially useful when the recursive call returns a value.

Example:

```java
int sum(int n) {

    if (n == 0) {
        return 0;
    }

    return n + sum(n - 1);
}
```

The relationship is:

```text
sum(n)
=
n + sum(n - 1)
```

For:

```text
sum(4)
```

we get:

```text
sum(4)
= 4 + sum(3)

sum(3)
= 3 + sum(2)

sum(2)
= 2 + sum(1)

sum(1)
= 1 + sum(0)

sum(0)
= 0
```

Return phase:

```text
sum(0) = 0
sum(1) = 1
sum(2) = 3
sum(3) = 6
sum(4) = 10
```

---

# 9. Linear Recursion Pattern: Accumulation

Many problems follow:

```text
answer(n)
=
currentValue + answer(n-1)
```

Examples:

```text
sum
factorial
count
product
some array calculations
```

### Sum

```java
int sum(int n) {
    if (n == 0) return 0;

    return n + sum(n - 1);
}
```

### Factorial

```java
int factorial(int n) {
    if (n == 0) return 1;

    return n * factorial(n - 1);
}
```

The structure is the same:

```text
current value
      +
smaller answer
```

or:

```text
current value
      *
smaller answer
```

int factorial(int n) {

      3 × factorial(2)

Returning:

```text
1
↑

↑
2 × 1 = 2
↑
3 × 2 = 6
↑
4 × 6 = 24
↑
5 × 24 = 120
```

# 11. Example — Power

```java
int power(int x, int n) {

    if (n == 0) {
        return 1;
    }

    return x * power(x, n - 1);
}
```

Relationship:

```text
power(x, n)
=
x × power(x, n-1)
```

For:

```text
power(2, 4)
```

       ↓
2 × power(2,2)

       ↓

# 12. Linear Recursion With an Index

Linear recursion doesn't require `n`.

Often we recursively move through an array or string.

Example:

```java
void printArray(int[] arr, int index) {

    if (index == arr.length) {
        return;
    }

    System.out.println(arr[index]);

    printArray(arr, index + 1);
}
```

For:

```text
arr = [10, 20, 30, 40]
```

Calls:

```text
printArray(0)
      ↓
printArray(1)
      ↓
printArray(2)
      ↓
printArray(3)
      ↓
printArray(4)
      ↓
return
```

Output:

```text
10
20
30
40
```

Here the recursive state is:

```text
index
```

not `n`.

---

# 13. The Meaning of the Index

Before writing:

```java
printArray(arr, index)
```

define what `index` means.

A good definition:

> **`printArray(arr, index)` means: print all elements from `index` to the end.**

Therefore:

```text
printArray(0)
```

means:

```text
print 0 → end
```

and:

```text
printArray(1)
```

means:

```text
print 1 → end
```

This function definition makes the recursive solution natural.

---

# 14. Linear Recursion on a Range

Sometimes we use two boundaries.

Example:

```java
boolean palindrome(String s, int left, int right) {

    if (left >= right) {
        return true;
    }

    if (s.charAt(left) != s.charAt(right)) {
        return false;
    }

    return palindrome(s, left + 1, right - 1);
}
```

There is still only **one recursive call**.

So this is linear recursion.

The state changes:

```text
[left, right]
      ↓
[left+1, right-1]
      ↓
[left+2, right-2]
```

Example:

```text
[0, 4]
  ↓
[1, 3]
  ↓
[2, 2]
  ↓
stop
```

# 15. Linear Recursion and Problem Size

A useful way to recognize linear recursion:

```text
Problem size:
N
↓
N-1
↓
N-2
↓
N-3
```

or:

```text
N
↓
N/2
↓
N/4
↓
N/8
```

As long as there is only **one recursive branch**, it can still be linear recursion.

For example, binary search:

```text
search(N)
   ↓
search(N/2)
   ↓
search(N/4)
   ↓
...
```

There is one recursive call at each level.

---

# 16. Linear Recursion Does NOT Mean O(N)

This is an important distinction.

**Linear recursion** describes the **number of recursive calls per function call**.

It does not automatically mean:

```text
O(N)
```

Example:

```text
f(N)
 ↓
f(N-1)
```

has approximately `N` calls:

```text
O(N)
```

But binary search:

```text
f(N)
 ↓
f(N/2)
 ↓
f(N/4)
 ↓
...
```

has:

```text
O(log N)
```

Both have one recursive call per function.

Therefore:

> **Linear recursion ≠ necessarily O(N).**

---

# 17. Time Complexity of Linear Recursion

The complexity depends on how much work is done at each level and how quickly the problem shrinks.

### Case 1

```text
N → N-1
```

Number of calls:

```text
N
```

If each call does `O(1)` work:

```text
Time = O(N)
```

---

### Case 2

```text
N → N/2
```

Number of calls:

```text
log N
```

If each call does `O(1)` work:

```text
Time = O(log N)
```

---

### Case 3

Each call performs an `O(N)` loop:

```text
f(N)
 ↓
f(N-1)
 ↓
f(N-2)
```

Then:

```text
O(N) + O(N-1) + O(N-2) + ...
```

which becomes:

```text
O(N²)
```

So always analyze:

```text
Number of recursive calls
+
Work performed at each call
```

---

# 18. Space Complexity

Linear recursion uses the call stack.

Example:

```java
void f(int n) {

    if (n == 0) return;

    f(n - 1);
}
```

For:

```text
f(5)
```

the stack can contain:

```text
f(5)
f(4)
f(3)
f(2)
f(1)
f(0)
```

Maximum depth:

```text
O(N)
```

Therefore auxiliary space:

```text
O(N)
```

for `n → n-1` recursion.

---

# 19. Tail Recursion

A special form of linear recursion is **tail recursion**.

The recursive call is the **last operation** performed by the function.

Example:

```java
void print(int n) {

    if (n == 0) return;

    System.out.println(n);

    print(n - 1);
}
```

After:

```java
print(n - 1);
```

there is nothing left to do.

Therefore the recursive call is in the **tail position**.

---

# 20. Non-Tail Recursion

Example:

```java
int factorial(int n) {

    if (n == 0) return 1;

    return n * factorial(n - 1);
}
```

The recursive call happens inside:

```text
n * factorial(n - 1)
```

After `factorial(n - 1)` returns, multiplication still needs to happen.

Therefore this is **not tail recursion**.

Compare:

```text
Tail recursion:
    recursive call
    ↓
    nothing left

Non-tail:
    recursive call
    ↓
    more work remains
```

---

# 21. Tail Recursion With an Accumulator

Factorial can be rewritten:

```java
int factorial(int n, int result) {

    if (n == 0) {
        return result;
    }

    return factorial(n - 1, result * n);
}
```

Call:

```java
factorial(5, 1);
```

State:

```text
factorial(5, 1)
factorial(4, 5)
factorial(3, 20)
factorial(2, 60)
factorial(1, 120)
factorial(0, 120)
```

Answer:

```text
120
```

The `result` parameter carries the accumulated answer.

# 22. Two Ways to Think About Linear Recursion

### Style 1 — Return from the bottom

```java
return n + sum(n - 1);
```

Think:

```text
Go down
   ↓
Get smaller answer
   ↓
Combine while returning
```

---

### Style 2 — Carry the answer

```java
sum(n, result)
```

Think:

```text
Current answer is already stored
       ↓
Update it
       ↓
Go to smaller problem
```

These are two different ways to structure the same linear process.

# 23. Linear Recursion Problem Patterns

Most beginner linear recursion problems fall into a few categories.

## Pattern A — Simple Traversal

```text
index → index + 1
```

Examples:

- Print array
- Search element
- Count elements
- Find first occurrence

---

## Pattern B — Accumulation

```text
answer + current
```

Examples:

- Sum
- Product
- Count
- Maximum
- Minimum

---

## Pattern C — Two-Pointer Shrinking

```text
left + 1
right - 1
```

Examples:

- Palindrome
- Reverse string
- Compare from both ends

---

## Pattern D — Divide the Problem

```text
N → N/2
```

Examples:

- Binary search
- Some divide-and-conquer problems

# 24. Example — Find Maximum

```java
int max(int[] arr, int index) {

    if (index == arr.length - 1) {
        return arr[index];
    }

    int smallerAnswer = max(arr, index + 1);

    return Math.max(arr[index], smallerAnswer);
}
```

Function meaning:

> `max(arr, index)` returns the maximum element from `index` to the end.

Thinking:

```text
max(index)
    =
max(
    current element,
    max(index + 1)
)
```

Trust:

```text
max(index + 1)
```

Then compare it with:

```text
arr[index]
```

---

# 25. Example — Count Occurrences

Problem:

```text
arr = [2, 5, 2, 7, 2]
target = 2
```

We want:

```text
3
```

Recursive thinking:

```text
count(index)
=
current match
+
count(index + 1)
```

Code:

```java
int count(int[] arr, int index, int target) {

    if (index == arr.length) {
        return 0;
    }

    int current = (arr[index] == target) ? 1 : 0;

    return current + count(arr, index + 1, target);
}
```

The recursion handles the rest of the array.

---

# 26. Example — Search an Element

```java
boolean contains(int[] arr, int index, int target) {

    if (index == arr.length) {
        return false;
    }

    if (arr[index] == target) {
        return true;
    }

    return contains(arr, index + 1, target);
}
```

Thinking:

```text
Does current element match?
        |
     YES → true
        |
       NO
        ↓
Ask recursion to search the rest.
```

# 27. How to Identify Linear Recursion

When looking at recursive code, ask:

### Question 1

How many recursive calls are made?

```java
f(n - 1);
```

One → potentially linear recursion.

### Question 2

Does each call create only one next call?

```text
f(5)
 ↓
f(4)
 ↓
f(3)
```

Yes → linear structure.

### Question 3

Does it branch?

```java
f(n - 1);
f(n - 2);
```

Then:

```text
        f(n)
       /    \
   f(n-1)  f(n-2)
```

That's no longer linear recursion.

---

# 28. Linear Recursion vs Iteration

Consider:

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

and:

```java
void print(int i, int n) {

    if (i == n) return;

    System.out.println(i);

    print(i + 1, n);
}
```

The logical process is almost identical:

```text
Loop:
i → i + 1

Recursion:
i → i + 1
```

The major difference is how the repeated state is managed.

### Loop

The loop controls the state.

### Recursion

The call stack stores each unfinished function call.

# 29. Converting a Linear Loop to Recursion

Use this method:

```text
1. Find loop variable
       ↓
2. Make it a parameter
       ↓
3. Find loop stopping condition
       ↓
4. Make it the base case
       ↓
5. Copy loop body
       ↓
6. Replace update with recursive call
```

Example:

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

Becomes:

```java
void f(int i, int n) {

    if (i == n) {
        return;
    }

    System.out.println(i);

    f(i + 1, n);
}
```

# 30. Dry Run Template

For linear recursion, use a simple table.

Example:

```java
int sum(int n) {

    if (n == 0) return 0;

    return n + sum(n - 1);
}
```

For `sum(4)`:

```text
Call        Waiting for
-------------------------
sum(4)      4 + sum(3)
sum(3)      3 + sum(2)
sum(2)      2 + sum(1)
sum(1)      1 + sum(0)
sum(0)      0
```

Then:

```text
sum(0) = 0
sum(1) = 1
sum(2) = 3
sum(3) = 6
sum(4) = 10
```

The key word is:

> **Waiting**

Every unfinished recursive call is waiting for the smaller call to return.

# 31. The Most Important Linear Recursion Insight

A function call can be thought of as:

```text
"I will handle my current part."

"Recursion, you handle the rest."

"I'll wait for your answer."

"Then I'll finish my part."
```

Example:

```java
return arr[index] + sum(arr, index + 1);
```

Means:

```text
"I handle arr[index]."

"Recursion handles index+1 onward."

"Give me that answer."

"I combine both."
```

This is the essence of linear recursion.

# 32. Common Mistakes

## Mistake 1 — Forgetting the Base Case

```java
void f(int n) {
    f(n - 1);
}
```

❌ Infinite recursion.

---

## Mistake 2 — Not Moving Toward the Base Case

```java
void f(int n) {

    if (n == 0) return;

    f(n + 1);
}
```

❌ Moving away from `0`.

---

## Mistake 3 — Making Two Calls Accidentally

```java
f(n - 1);
f(n - 2);
```

❌ This creates branching recursion.

---

## Mistake 4 — Losing the Recursive Answer

Wrong:

```java
int sum(int n) {

    if (n == 0) return 0;

    sum(n - 1);

    return n;
}
```

The result from:

```text
sum(n - 1)
```

is ignored.

Correct:

```java
return n + sum(n - 1);
```

---

## Mistake 5 — Confusing Down and Up

Remember:

```text
Before recursive call
→ DOWN

After recursive call
→ UP
```

# 33. Linear Recursion Checklist

When solving a problem, ask:

```text
1. Is there only one recursive call?

2. What does my function mean?

3. What is the smallest problem?

4. What is my base case?

5. What becomes smaller?

6. What does the recursive call solve?

7. What happens before recursion?

8. What happens after recursion?

9. If recursion returns an answer,
   how do I use it?

10. How many calls are made?

11. How deep can the call stack become?

12. Is the recursive call tail-recursive?
```

# 36. Golden Rules

> **Rule 1:** Linear recursion has at most one recursive call per function call.

> **Rule 2:** Define what your function means before writing the recursive call.

> **Rule 3:** The recursive call should represent a smaller version of the current problem.

> **Rule 4:** Trust the recursive call to solve the smaller problem.

> **Rule 5:** Work before recursion happens while going DOWN.

> **Rule 6:** Work after recursion happens while coming BACK UP.

> **Rule 7:** Linear recursion does not necessarily mean `O(N)` time.

> **Rule 8:** Always consider call-stack space.

> **Rule 9:** If the recursive call is the last operation, it is tail recursion.

---

# 37. One-Line Summary

> **Linear recursion = solve a problem by making one recursive call that moves to a smaller state, eventually reaching a base case and returning through the call stack.**

### Core Pattern

```text
              solve(state)
                   |
                   ↓
             base case?
              /       \
            YES        NO
             |          |
           return    current work
                         |
                         ↓
                  solve(smaller)
                         |
                         ↓
                    get answer
                         |
                         ↓
                  finish current
```
