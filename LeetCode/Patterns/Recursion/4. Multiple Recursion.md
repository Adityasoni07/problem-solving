# 4. Multiple Recursion

> **Goal:** Understand recursion where **one function call makes multiple recursive calls**, creating a recursion tree.

---

# 1. What Is Multiple Recursion?

In **linear recursion**, each function call makes at most one recursive call:

```java
f(n)
 ↓
f(n - 1)
 ↓
f(n - 2)
```

In **multiple recursion**, one function call makes **two or more recursive calls**:

```java
f(n)
├── f(n - 1)
└── f(n - 2)
```

Example:

```java
void f(int n) {

    if (n <= 1) {
        return;
    }

    f(n - 1);
    f(n - 2);
}
```

For `f(4)`:

```text
                 f(4)
                /    \
             f(3)    f(2)
             /  \     /  \
          f(2) f(1) f(1) f(0)
          / \
       f(1) f(0)
```

This branching structure is why multiple recursion is often called **tree recursion**.

---

# 2. Linear vs Multiple Recursion

## Linear Recursion

```java
f(n - 1);
```

```text
f(4)
 ↓
f(3)
 ↓
f(2)
 ↓
f(1)
```

One path.

---

## Multiple Recursion

```java
f(n - 1);
f(n - 2);
```

```text
        f(4)
       /    \
    f(3)    f(2)
    /  \    /  \
  f(2) f(1) f(1) f(0)
```

Multiple paths.

### Key Difference

```text
Linear:
ONE recursive call

Multiple:
TWO OR MORE recursive calls
```

---

# 3. The Most Important Mental Model

With linear recursion:

```text
CURRENT
   ↓
SMALLER
   ↓
SMALLER
   ↓
BASE
```

With multiple recursion:

```text
              CURRENT
              /     \
             /       \
        SMALLER     SMALLER
          / \         / \
         /   \       /   \
      ...   ...    ...   ...
```

Each recursive call creates its **own independent problem**.

This is the biggest mental shift from linear recursion.

---

# 4. Example — Fibonacci

The classic example:

```text
F(0) = 0
F(1) = 1

F(n) = F(n-1) + F(n-2)
```

Code:

```java
int fib(int n) {

    if (n <= 1) {
        return n;
    }

    return fib(n - 1) + fib(n - 2);
}
```

For:

```java
fib(4)
```

the recursion tree is:

```text
                    fib(4)
                   /      \
              fib(3)      fib(2)
              /   \        /   \
          fib(2) fib(1) fib(1) fib(0)
          /   \
      fib(1) fib(0)
```

Notice:

```text
fib(4)
```

doesn't solve the entire problem itself.

It says:

```text
I need:
    fib(3)
AND
    fib(2)
```

Then each of those creates its own problems.

---

# 5. The Key Thinking Pattern

For multiple recursion, ask:

> **"What are the smaller subproblems I need to solve?"**

For Fibonacci:

```text
fib(n)
=
fib(n-1)
+
fib(n-2)
```

So:

```text
Current problem
      ↓
 ┌────┴────┐
 ↓         ↓
Problem 1  Problem 2
 ↓         ↓
Answer 1   Answer 2
 └────┬────┘
      ↓
Combine
```

---

# 6. Recursive Trust Still Applies

Multiple recursion does **not** change the trust principle.

For:

```java
return fib(n - 1) + fib(n - 2);
```

don't manually calculate:

```text
fib(n-1)
```

and:

```text
fib(n-2)
```

Instead:

> **Trust the first recursive call to solve the first subproblem.**

and:

> **Trust the second recursive call to solve the second subproblem.**

Then combine their answers.

```text
fib(n)
=
answer from left branch
+
answer from right branch
```

---

# 7. Multiple Recursion Has a Tree

Linear recursion:

```text
f(5)
 ↓
f(4)
 ↓
f(3)
 ↓
f(2)
```

Multiple recursion:

```text
             f(5)
            /    \
         f(4)    f(3)
         / \      / \
      f(3) f(2) f(2) f(1)
      ...
```

The structure is a **recursion tree**.

Each node represents one function call.

Each edge represents a recursive call.

---

# 8. How to Read a Recursion Tree

For:

```java
f(n - 1);
f(n - 2);
```

think:

```text
                 f(n)
                /    \
               /      \
          f(n-1)      f(n-2)
```

Then expand each independently:

```text
                 f(n)
                /    \
           f(n-1)    f(n-2)
           /   \      /   \
      f(n-2) f(n-3) f(n-3) f(n-4)
```

Important:

> **Each branch is its own recursive execution.**

---

# 9. Example — Fibonacci Dry Run

Let's calculate:

```java
fib(4)
```

### Step 1

```text
fib(4)
```

needs:

```text
fib(3) + fib(2)
```

### Step 2

```text
fib(3)
```

needs:

```text
fib(2) + fib(1)
```

### Step 3

```text
fib(2)
```

needs:

```text
fib(1) + fib(0)
```

Complete tree:

```text
                     fib(4)
                    /      \
                 fib(3)    fib(2)
                /    \      /    \
             fib(2) fib(1) fib(1) fib(0)
             /   \
          fib(1) fib(0)
```

Base cases:

```text
fib(1) = 1
fib(0) = 0
```

Returning upward:

```text
fib(2) = 1 + 0 = 1

fib(3) = 1 + 1 = 2

fib(2) = 1
```

Finally:

```text
fib(4) = 2 + 1 = 3
```

---

# 10. The Big Problem: Repeated Work

Look carefully at the tree:

```text
                     fib(4)
                    /      \
                 fib(3)    fib(2)
                /    \      /    \
             fib(2) fib(1) fib(1) fib(0)
```

`fib(2)` is calculated more than once.

And inside larger inputs, the repetition grows rapidly.

For example:

```text
fib(5)
```

contains repeated calls such as:

```text
fib(3)
fib(2)
fib(2)
fib(1)
...
```

This is why naive recursive Fibonacci is inefficient.

---

# 11. Time Complexity

For naive Fibonacci:

```java
fib(n - 1);
fib(n - 2);
```

the number of calls grows exponentially.

Approximate complexity:

```text
O(2^N)
```

More precisely, it is often described as:

```text
O(φ^N)
```

where `φ` is the golden ratio.

For learning purposes, remember:

> **Naive Fibonacci recursion is exponential because the recursion tree branches and repeatedly solves the same subproblems.**

---

# 12. Space Complexity

Although there are many nodes in the recursion tree, the call stack only contains the **current path**.

For Fibonacci:

```text
fib(n)
 ↓
fib(n-1)
 ↓
fib(n-2)
 ↓
...
```

Maximum recursion depth is approximately:

```text
O(N)
```

So:

```text
Time  → O(2^N)
Space → O(N)
```

The distinction is important:

```text
Total tree nodes ≠ Maximum call-stack depth
```

---

# 13. Multiple Recursion Is Not Always Bad

Multiple recursion is useful when the problem naturally splits into independent subproblems.

Examples:

```text
Fibonacci
Merge Sort
Quick Sort
Tree traversal
Backtracking
Subsets
Permutations
Combinations
```

The problem is not:

> "Multiple recursion is inefficient."

The real question is:

> **"Does the problem naturally branch?"**

If yes, recursion may be the natural solution.

---

# 14. Multiple Recursion With Arrays

Suppose you want to generate all subsets.

For each element, you have two choices:

```text
Take it
OR
Don't take it
```

So:

```text
                  element
                 /       \
              TAKE      DON'T TAKE
               /           \
           problem       problem
```

Code structure:

```java
void solve(int index) {

    if (index == n) {
        // process answer
        return;
    }

    // Choice 1
    solve(index + 1);

    // Choice 2
    solve(index + 1);
}
```

This is multiple recursion because:

```text
solve(index)
```

creates:

```text
solve(index + 1)
solve(index + 1)
```

---

# 15. Multiple Recursion + Choices

A powerful way to recognize multiple recursion:

> **If at every step you have multiple choices, each choice may become a recursive branch.**

Example:

```text
                 Choose?
                /       \
              YES        NO
               |          |
            recurse    recurse
```

This idea becomes extremely important in:

- Subsets
- Subsequences
- Combinations
- Permutations
- Backtracking

---

# 16. Example — Subsets

Given:

```text
[1, 2]
```

For `1`:

```text
             1
           /   \
        TAKE   SKIP
```

Then for `2`:

```text
               []
             /    \
            1      []
          /  \    /  \
        1,2  1    2   []
```

Final subsets:

```text
[]
[1]
[2]
[1,2]
```

The important point:

```text
Every element creates two choices:
    include
    exclude
```

That creates a recursion tree.

---

# 17. Multiple Recursion vs Backtracking

They are related but not identical.

### Multiple recursion

Focus:

```text
One call
   ↓
Multiple recursive calls
```

### Backtracking

Usually:

```text
Make choice
   ↓
Recurse
   ↓
Undo choice
   ↓
Make another choice
```

Example:

```java
path.add(x);

solve(index + 1);

path.remove(path.size() - 1);
```

The `remove()` is the **backtracking** step.

So:

```text
Multiple recursion
        ↓
Branching

Backtracking
        ↓
Branching + state modification + undo
```

---

# 18. Multiple Recursion With Divide and Conquer

Multiple recursion can also split a problem into independent halves.

Example: Merge Sort.

```text
                array
               /     \
          left half  right half
             /           \
        left-left      right-right
```

Conceptually:

```text
sort(array)
    |
    ├── sort(left)
    |
    └── sort(right)
```

Then:

```text
merge(left, right)
```

combines the results.

This is another important multiple-recursion pattern.

---

# 19. General Multiple Recursion Template

A general form:

```java
returnType solve(state) {

    if (baseCase) {
        return baseAnswer;
    }

    Answer a = solve(smallerState1);

    Answer b = solve(smallerState2);

    return combine(a, b);
}
```

Think:

```text
                 solve(state)
                    |
             ┌──────┴──────┐
             ↓             ↓
       solve(state1)  solve(state2)
             ↓             ↓
          answer 1       answer 2
             └──────┬──────┘
                    ↓
                 combine
```

This is the fundamental structure.

---

# 20. Multiple Recursive Calls Can Have Different Problems

They don't always have to be:

```text
n - 1
n - 2
```

For example:

```java
solve(leftHalf);
solve(rightHalf);
```

or:

```java
solve(index + 1, take);
solve(index + 1, skip);
```

or:

```java
solve(left + 1, right);
solve(left, right - 1);
```

The key is:

```text
ONE CURRENT PROBLEM
        ↓
MULTIPLE SMALLER PROBLEMS
```

---

# 21. How to Think About Multiple Recursion

Use this sequence:

```text
1. Define the function.

2. Find the base case.

3. Identify all possible smaller subproblems.

4. Make one recursive call for each subproblem.

5. Trust each recursive call.

6. Combine/process their results.
```

---

# 22. Example — Fibonacci Thinking

Function meaning:

```text
fib(n)
→ returns the nth Fibonacci number.
```

Base case:

```text
n <= 1
```

Smaller problems:

```text
fib(n - 1)
fib(n - 2)
```

Combine:

```text
fib(n - 1) + fib(n - 2)
```

Code:

```java
int fib(int n) {

    if (n <= 1) {
        return n;
    }

    int left = fib(n - 1);
    int right = fib(n - 2);

    return left + right;
}
```

This version is often easier to understand than writing everything in one line.

---

# 23. Naming Branches Helps

Instead of:

```java
return fib(n - 1) + fib(n - 2);
```

temporarily write:

```java
int left = fib(n - 1);
int right = fib(n - 2);

return left + right;
```

Now your thinking becomes:

```text
left branch
    ↓
left answer

right branch
    ↓
right answer

combine
    ↓
final answer
```

This is especially useful when learning recursion trees.

---

# 24. Don't Mix the Branches

This is a common beginner mistake.

For:

```java
int left = fib(n - 1);
int right = fib(n - 2);
```

First:

```text
fib(n - 1)
```

must finish.

Then:

```text
fib(n - 2)
```

starts.

So execution is:

```text
             fib(n)
                |
          ┌─────┴─────┐
          ↓           ↓
      fib(n-1)      fib(n-2)
          ↓           ↓
       finish       finish
          └─────┬─────┘
                ↓
              combine
```

The recursion tree represents the structure of calls, while the call stack still executes one active path at a time.

---

# 25. Recursion Tree vs Call Stack

Don't confuse these.

### Recursion Tree

Shows:

```text
ALL recursive calls
```

Example:

```text
       f(4)
      /    \
   f(3)    f(2)
   /  \
 f(2) f(1)
```

### Call Stack

Shows:

```text
CURRENT ACTIVE PATH
```

For example, while evaluating the left branch:

```text
┌──────┐
│ f(1) │
├──────┤
│ f(2) │
├──────┤
│ f(3) │
├──────┤
│ f(4) │
└──────┘
```

The entire recursion tree is not sitting in the call stack simultaneously.

---

# 26. Complexity of Multiple Recursion

For complexity, ask:

```text
How many branches?
        +
How much work per node?
        +
How much does the problem shrink?
```

### Example

```text
T(n) = T(n-1) + T(n-2) + O(1)
```

This gives exponential growth.

### Divide and conquer

```text
T(n) = 2T(n/2) + O(n)
```

This gives:

```text
O(n log n)
```

as in merge sort.

So multiple recursion does **not automatically mean `O(2^N)`**.

It depends on the recurrence.

---

# 27. Common Mistakes

## Mistake 1 — Thinking Multiple Calls Execute Simultaneously

They don't.

```java
f(n - 1);
f(n - 2);
```

The first call must return before the second call starts.

---

## Mistake 2 — Not Understanding the Tree

If you see:

```java
f(n - 1);
f(n - 2);
```

immediately visualize:

```text
        f(n)
       /    \
  f(n-1)  f(n-2)
```

---

## Mistake 3 — Forgetting to Combine Answers

For:

```java
int left = solve(...);
int right = solve(...);
```

you usually need:

```text
combine(left, right)
```

Examples:

```java
return left + right;
```

or:

```java
return Math.max(left, right);
```

or:

```java
return left || right;
```

depending on the problem.

---

## Mistake 4 — Assuming Every Branch Is the Same

Branches can represent different choices or different subproblems.

Always understand:

```text
What does branch 1 mean?

What does branch 2 mean?
```

---

# 28. Multiple Recursion Checklist

Before coding:

```text
1. What does solve(state) mean?

2. What is the base case?

3. How many smaller problems exist?

4. What does each branch represent?

5. What does branch 1 return?

6. What does branch 2 return?

7. How do I combine the results?

8. Are the same subproblems repeated?

9. What is the recursion depth?

10. What is the time complexity?
```

# 32. Golden Rules

> **Rule 1:** Multiple recursion means one function call creates multiple recursive calls.

> **Rule 2:** Visualize multiple recursion as a tree.

> **Rule 3:** Each branch represents an independent subproblem or choice.

> **Rule 4:** Trust each recursive call to solve its own subproblem.

> **Rule 5:** After the branches return, combine their answers.

> **Rule 6:** Recursion tree ≠ call stack. The tree shows all calls; the stack shows the current active path.

> **Rule 7:** Multiple recursion does not automatically mean exponential complexity.

> **Rule 8:** Repeated subproblems are a major reason naive multiple recursion can be slow.

> **Rule 9:** Choice-based multiple recursion is the foundation for subsets, permutations, combinations, and backtracking.

# 33. One-Line Summary

> **Multiple recursion = solve a problem by dividing it into multiple smaller recursive subproblems, solving each branch, and combining or processing their results.**

### Core Pattern

```text
                    solve(problem)
                         |
                  ┌──────┴──────┐
                  ↓             ↓
             solve(A)       solve(B)
                  ↓             ↓
              answer A       answer B
                  └──────┬──────┘
                         ↓
                       combine
                         ↓
                    final answer
```

### The Most Important Transition

```text
Linear Recursion
       ↓
one path

Multiple Recursion
       ↓
multiple paths

Backtracking
       ↓
multiple paths + choices + undo
```

**Master `509 → 70 → 104 → 100 → 912 → 78` before moving deeper into backtracking.**
