# 5. Recursion Trees

> **Goal:** Learn how to visualize, trace, and analyze recursive calls using a **recursion tree** without getting lost in the execution.

---

# 1. What Is a Recursion Tree?

A **recursion tree** is a visual representation of recursive function calls.

Every function call becomes a **node**.

Every recursive call becomes a **child**.

For example:

```java
void f(int n) {

    if (n == 0) return;

    f(n - 1);
    f(n - 2);
}
```

For:

```java
f(4);
```

the recursion tree is:

```text
                    f(4)
                  /      \
               f(3)      f(2)
              /   \      /   \
           f(2)  f(1)  f(1)  f(0)
           /  \
        f(1) f(0)
```

The tree shows the **structure of recursive calls**.

---

# 2. Why Recursion Trees Matter

Recursion trees help you understand:

1. **How recursion branches**
2. **How many function calls happen**
3. **What order calls are created**
4. **Where the base cases occur**
5. **Where repeated work occurs**
6. **How recursion returns**
7. **Time complexity**
8. **Space/depth of recursion**

For difficult recursion problems, the tree can make the logic much easier to see.

---

# 3. Recursion Tree vs Call Stack

These are NOT the same thing.

## Recursion Tree

Shows:

```text
ALL recursive calls
```

Example:

```text
             f(4)
            /    \
         f(3)    f(2)
         /  \    /  \
      f(2) f(1) f(1) f(0)
```

---

## Call Stack

Shows:

```text
CURRENT ACTIVE CALL PATH
```

For example, while executing the left side:

```text
┌─────────┐
│  f(1)   │
├─────────┤
│  f(2)   │
├─────────┤
│  f(3)   │
├─────────┤
│  f(4)   │
└─────────┘
```

Then `f(1)` returns.

The program goes back to `f(2)`.

Then eventually it explores the other branch.

### Remember

```text
Recursion Tree
    ↓
All possible function calls

Call Stack
    ↓
Current active path
```

---

# 4. How to Build a Recursion Tree

Given:

```java
f(n - 1);
f(n - 2);
```

Start with:

```text
f(n)
```

Then create one child for every recursive call:

```text
       f(n)
      /    \
 f(n-1)  f(n-2)
```

Now expand each child.

For `f(4)`:

```text
             f(4)
            /    \
         f(3)    f(2)
```

Expand `f(3)`:

```text
             f(4)
            /    \
         f(3)    f(2)
        /   \
     f(2)  f(1)
```

Expand `f(2)`:

```text
             f(4)
            /    \
         f(3)    f(2)
        /   \     / \
     f(2) f(1) f(1) f(0)
```

Then stop expanding when you reach the base case.

---

# 5. The Base Case Creates the Leaves

Consider:

```java
if (n <= 1) return;
```

Those calls become the **leaf nodes** of the recursion tree.

Example:

```text
                  f(4)
                 /    \
              f(3)    f(2)
             /   \    /   \
          f(2) f(1) f(1) f(0)
          /   \
       f(1)  f(0)
```

The leaves are:

```text
f(1)
f(1)
f(1)
f(0)
f(1)
f(0)
```

No more recursive calls happen from them.

---

# 6. A Very Important Rule

> **Never expand beyond the base case.**

If:

```java
if (n <= 1) return;
```

then:

```text
f(1)
f(0)
```

are terminal nodes.

Don't create:

```text
f(1)
 ↓
f(0)
 ↓
f(-1)
```

because the function already returned at `f(1)`.

---

# 7. Example — Fibonacci Tree

The classic recursion-tree example:

```java
int fib(int n) {

    if (n <= 1) {
        return n;
    }

    return fib(n - 1) + fib(n - 2);
}
```

For:

```text
fib(5)
```

tree:

```text
                         fib(5)
                       /        \
                   fib(4)       fib(3)
                  /     \       /     \
              fib(3)   fib(2) fib(2) fib(1)
              /   \     /  \   /  \
          fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
          /   \
      fib(1) fib(0)
```

This immediately shows:

```text
fib(3)
```

appears multiple times.

And:

```text
fib(2)
```

appears even more than once.

---

# 8. Repeated Subproblems

This is one of the biggest reasons recursion trees are useful.

Look at:

```text
                         fib(5)
                       /        \
                   fib(4)       fib(3)
                  /     \       /     \
              fib(3)   fib(2) fib(2) fib(1)
```

We calculate:

```text
fib(3)
```

more than once.

We calculate:

```text
fib(2)
```

more than once.

This means the algorithm is doing **duplicate work**.

---

# 9. Recursion Tree → Dynamic Programming

When you see:

```text
             f(5)
            /    \
         f(4)    f(3)
         /  \    /  \
      f(3) f(2) f(2) f(1)
```

and notice:

```text
f(3)
f(2)
```

are repeated, ask:

> **"Can I calculate this subproblem once and reuse its answer?"**

That leads directly to **memoization / dynamic programming**.

Without memoization:

```text
Same subproblem
     ↓
calculate again
```

With memoization:

```text
Same subproblem
     ↓
answer already stored
     ↓
reuse answer
```

---

# 10. Recursion Tree and Time Complexity

A recursion tree can help estimate time complexity.

Suppose:

```java
f(n) {
    f(n - 1);
    f(n - 2);
}
```

Ignoring the exact Fibonacci recurrence for a moment, each non-base node creates roughly **two children**.

The tree grows approximately like:

```text
Level 0:        1 node

Level 1:        2 nodes

Level 2:        4 nodes

Level 3:        8 nodes

Level 4:       16 nodes
```

So the number of nodes grows exponentially.

Roughly:

```text
1 + 2 + 4 + 8 + ... + 2^n
```

Therefore:

```text
O(2^N)
```

is a useful upper-bound intuition for this type of recursion.

---

# 11. Tree Height vs Number of Nodes

This distinction is extremely important.

Consider:

```text
             f(5)
            /    \
         f(4)    f(3)
         /  \
      f(3)  f(2)
```

### Height

The longest path from root to leaf.

### Number of Nodes

Total function calls.

These can be very different.

For binary branching:

```text
Height ≈ N

Nodes ≈ 2^N
```

Therefore:

```text
Time  → potentially O(2^N)
Space → potentially O(N)
```

The stack only needs to store the current path.

---

# 12. How to Find Recursion Depth

Follow the **longest single path**.

For:

```text
f(n)
 ↓
f(n-1)
 ↓
f(n-2)
 ↓
...
 ↓
f(0)
```

depth is approximately:

```text
N
```

Therefore stack space:

```text
O(N)
```

Even if the entire recursion tree contains exponentially many nodes.

---

# 13. Example — Binary Search Tree Shape

Consider:

```text
search(n)
    ↓
search(n/2)
    ↓
search(n/4)
    ↓
search(n/8)
```

This recursion tree doesn't branch if there is only one recursive call.

It is really a chain:

```text
search(n)
   ↓
search(n/2)
   ↓
search(n/4)
   ↓
search(n/8)
   ↓
...
```

Number of levels:

```text
log₂N
```

Therefore:

```text
Time  → O(log N)
Space → O(log N)
```

---

# 14. Not Every Recursion Tree Is Huge

Compare:

### Linear recursion

```text
f(n)
 ↓
f(n-1)
 ↓
f(n-2)
 ↓
f(n-3)
```

Structure:

```text
One long chain
```

### Binary recursion

```text
        f(n)
       /    \
   f(n-1)  f(n-2)
   /  \      /  \
  ... ...   ... ...
```

Structure:

```text
Branching tree
```

The number of children determines how quickly the tree can grow.

---

# 15. Recursion Tree With Work Per Node

Suppose:

```java
void f(int n) {

    if (n == 0) return;

    for (int i = 0; i < n; i++) {
        // O(n) work
    }

    f(n - 1);
    f(n - 2);
}
```

The tree tells us how many calls exist.

But we also need to consider:

```text
work done at each node
```

So complexity isn't determined by the tree structure alone.

General idea:

```text
Total Time
=
Sum of work done by every node
```

---

# 16. Recursion Tree for Merge Sort

Merge Sort has a very important recursion tree.

Conceptually:

```text
                         n
                       /   \
                     n/2   n/2
                    / \    / \
                  n/4 n/4 n/4 n/4
                 /...           ...
```

At every level, the array is divided into smaller pieces.

But the total amount of merging work at each level is approximately:

```text
O(N)
```

Number of levels:

```text
O(log N)
```

Therefore:

```text
O(N) × O(log N)
=
O(N log N)
```

This is a powerful use of recursion trees for complexity analysis.

---

# 17. Recursion Tree for Merge Sort

A simplified view:

```text
Level 0:
                         N

Level 1:
                    N/2     N/2

Level 2:
                N/4 N/4   N/4 N/4

Level 3:
              N/8 N/8 N/8 N/8 ...
```

At every level:

```text
Number of subproblems × size of each
```

equals approximately:

```text
N
```

So:

```text
Level 0 → N
Level 1 → N
Level 2 → N
Level 3 → N
...
```

There are:

```text
log N
```

levels.

Therefore:

```text
Time = N × log N
     = O(N log N)
```

---

# 18. The Recursion Tree Method

For a recursive algorithm, use this process:

### Step 1

Write the root:

```text
T(N)
```

### Step 2

Expand recursive calls.

Example:

```text
T(N)
├── T(N/2)
└── T(N/2)
```

### Step 3

Expand another level:

```text
                 T(N)
               /      \
           T(N/2)    T(N/2)
           /   \      /   \
      T(N/4) T(N/4) T(N/4) T(N/4)
```

### Step 4

Find the number of levels.

### Step 5

Find the work at each level.

### Step 6

Add the work across all levels.

---

# 19. Recursion Tree Formula

For a recurrence:

```text
T(N) = aT(N/b) + f(N)
```

the recursion tree helps us see:

```text
Level 0:
f(N)

Level 1:
a × f(N/b)

Level 2:
a² × f(N/b²)

Level 3:
a³ × f(N/b³)
```

Continue until:

```text
N / b^k = 1
```

which gives:

```text
k = log_b N
```

Then calculate the total work across levels.

---

# 20. Example — T(N) = 2T(N/2) + N

Tree:

```text
Level 0:

             N
```

Work:

```text
N
```

Level 1:

```text
          N/2       N/2
```

Total work:

```text
N/2 + N/2 = N
```

Level 2:

```text
      N/4 N/4    N/4 N/4
```

Total:

```text
N
```

Therefore:

```text
Level 0 → N
Level 1 → N
Level 2 → N
...
```

Number of levels:

```text
log N
```

Total:

```text
N × log N
```

Therefore:

```text
O(N log N)
```

---

# 21. A Better Way to Draw Trees

Don't create giant trees unnecessarily.

For understanding execution:

```text
              f(4)
             /    \
          f(3)    f(2)
```

is often enough.

For complexity:

```text
Level 0 → 1 node
Level 1 → 2 nodes
Level 2 → 4 nodes
Level 3 → 8 nodes
```

is usually more useful than writing every function call.

### Rule

> **Draw only as much of the tree as you need to answer the question.**

---

# 22. How to Dry Run a Recursion Tree

Suppose:

```java
int f(int n) {

    if (n <= 1) {
        return n;
    }

    int left = f(n - 1);
    int right = f(n - 2);

    return left + right;
}
```

For:

```text
f(4)
```

### Step 1 — Build the structure

```text
             f(4)
            /    \
         f(3)    f(2)
```

### Step 2 — Expand

```text
             f(4)
            /    \
         f(3)    f(2)
        /  \     /  \
     f(2) f(1) f(1) f(0)
```

### Step 3 — Expand remaining non-base node

```text
f(2)
├── f(1)
└── f(0)
```

### Step 4 — Start returning

```text
f(1) = 1
f(0) = 0

f(2) = 1
```

Then:

```text
f(3) = f(2) + f(1)
     = 1 + 1
     = 2
```

Finally:

```text
f(4) = f(3) + f(2)
     = 2 + 1
     = 3
```

---

# 23. Execution Order in a Tree

Suppose:

```java
f(n - 1);
f(n - 2);
```

The tree:

```text
             f(n)
            /    \
        f(n-1)   f(n-2)
```

does NOT mean both execute simultaneously.

Execution is:

```text
1. Enter f(n)

2. Execute f(n-1)

3. Completely finish f(n-1)

4. Return to f(n)

5. Execute f(n-2)

6. Completely finish f(n-2)

7. Return to f(n)

8. Continue current function
```

So the recursion tree represents **structure**, not simultaneous execution.

---

# 24. Recursion Tree and Return Flow

For:

```text
             f(4)
            /    \
         f(3)    f(2)
```

execution:

```text
             f(4)
               |
               ↓
             f(3)
            /    \
         f(2)    f(1)
           |
         return
           ↑
         f(3)
           |
         return
           ↑
         f(4)
           |
           ↓
         f(2)
```

Think:

```text
LEFT BRANCH
    ↓
finish
    ↓
RETURN
    ↓
RIGHT BRANCH
    ↓
finish
    ↓
RETURN
```

# 25. Recursion Tree and Repeated Work

Suppose:

```text
                  f(5)
                 /    \
              f(4)    f(3)
              /  \    /  \
           f(3) f(2) f(2) f(1)
```

Repeated:

```text
f(3)
f(2)
```

This tells you:

> **The algorithm may benefit from memoization.**

This is one of the most important reasons to learn recursion trees before Dynamic Programming.

---

# 26. Memoization Changes the Tree

Without memoization:

```text
             f(5)
            /    \
         f(4)    f(3)
         /  \      \
      f(3) f(2)    f(2)
```

Same problems are recalculated.

With memoization:

```text
             f(5)
            /    \
         f(4)    f(3)
         /  \      \
      f(3) f(2)    cached
```

Instead of creating another full subtree, we reuse the stored answer.

So:

```text
Recursion Tree
      ↓
See repeated subproblems
      ↓
Memoization
      ↓
Dynamic Programming
```

# 27. Common Recursion Tree Shapes

## Shape 1 — Chain

```text
f(n)
 ↓
f(n-1)
 ↓
f(n-2)
 ↓
f(n-3)
```

Usually one recursive call.

---

## Shape 2 — Binary Tree

```text
       f(n)
      /    \
 f(n-1)   f(n-2)
```

Two recursive calls.

---

## Shape 3 — Divide and Conquer

```text
          T(N)
         /    \
     T(N/2)  T(N/2)
```

---

## Shape 4 — Multiple Choices

```text
             solve
          /    |    \
       choice choice choice
```

Common in backtracking.

# 28. How Recursion Trees Help With Backtracking

Consider subsets.

For:

```text
[1,2,3]
```

each element gives:

```text
take
OR
skip
```

Tree:

```text
                       []
                    /      \
                 take      skip
                  1          1
                /  \       /  \
             take skip   take skip
               2    2       2    2
              / \  / \     / \  / \
             ... ... ...   ... ... ...
```

The recursion tree shows all possible choices.

This is the foundation of:

```text
Subsets
Subsequences
Combinations
Permutations
Backtracking
```

---

# 29. Don't Confuse Tree With Output

A recursion tree shows **function calls**.

It does not necessarily show the output directly.

For:

```java
void f(int n) {

    if (n == 0) return;

    System.out.println(n);

    f(n - 1);
}
```

Tree:

```text
f(3)
 |
f(2)
 |
f(1)
 |
f(0)
```

Output:

```text
3
2
1
```

The tree shows:

```text
calls
```

while the code determines:

```text
output
```

---

# 30. A Practical Recursion Tree Method

When you get stuck in a recursion problem:

```text
STEP 1
Write the first call.

        f(4)

STEP 2
Write every recursive call.

       f(4)
      /    \
   f(3)   f(2)

STEP 3
Expand non-base nodes.

STEP 4
Mark base cases.

STEP 5
Understand what each node returns.

STEP 6
Work from the leaves upward.

STEP 7
Check for repeated subproblems.

STEP 8
Estimate depth and total nodes if needed.
```

---

# 31. When NOT to Draw a Full Tree

For linear recursion:

```text
f(100)
 ↓
f(99)
 ↓
...
```

drawing every node is usually pointless.

Instead:

```text
f(n)
 ↓
f(n-1)
 ↓
...
 ↓
base
```

For a large branching recursion:

```text
f(20)
```

don't draw the entire tree.

Use:

```text
Level 0 → 1 node
Level 1 → 2 nodes
Level 2 → 4 nodes
...
```

This is much more useful for complexity.

---

# 32. Recursion Tree Checklist

Whenever you build a recursion tree, ask:

```text
1. What is the root call?

2. How many recursive calls does each node make?

3. What does each child represent?

4. Where are the base cases?

5. What are the leaf nodes?

6. What does each node return?

7. In what order are branches executed?

8. Are subproblems repeated?

9. What is the height of the tree?

10. How many nodes are there?

11. What work happens at each node?

12. What is the total time complexity?

13. What is the maximum recursion depth?
```

# 36. Golden Rules

> **Rule 1:** Every function call is a node.

> **Rule 2:** Every recursive call creates a child.

> **Rule 3:** Base cases are leaf nodes.

> **Rule 4:** The recursion tree shows structure, not simultaneous execution.

> **Rule 5:** The call stack contains only the current active path.

> **Rule 6:** Tree height helps determine recursion depth and stack space.

> **Rule 7:** Total nodes and work per node help determine time complexity.

> **Rule 8:** Repeated nodes/subproblems are a strong signal for memoization.

> **Rule 9:** Don't draw unnecessarily huge trees; use levels when analyzing complexity.

> **Rule 10:** In choice-based problems, each choice usually becomes a branch.

# 37. One-Line Summary

> **A recursion tree is a visual model of recursive calls that helps you understand branching, execution, repeated work, return flow, complexity, and recursion depth.**

### Core Mental Model

```text
                         PROBLEM
                            |
                 ┌──────────┴──────────┐
                 ↓                     ↓
             SUBPROBLEM 1          SUBPROBLEM 2
                 |                     |
          ┌──────┴──────┐       ┌──────┴──────┐
          ↓             ↓       ↓             ↓
        ...           ...     ...           ...
          |             |       |             |
          └─────────────┴───────┴─────────────┘
                            ↓
                         COMBINE
                            ↓
                       FINAL ANSWER
```

**Core progression:**

```text
Linear Recursion
      ↓
Multiple Recursion
      ↓
Recursion Trees
      ↓
Backtracking / Divide & Conquer / DP
```

The key skill is not drawing beautiful trees. It is being able to look at a recursive call and immediately understand:

> **"What branches are being created, what does each branch solve, and how do their answers come back together?"**
